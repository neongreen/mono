## Baseline Commit

All lint violations existing at this commit are allowed. New violations after this commit will fail CI.

## How it Works

The lint configuration uses `--new-from-rev=0c23a5a5` to only show violations introduced after the baseline commit.

- **In CI:** `.dagger/runlint.go` uses `--new-from-rev=0c23a5a5`
- **Locally:** `mise run lint:go:golangci` uses the same flag

When violations are fixed, update the baseline commit:

1. Fix some violations
2. Commit the fixes
3. Update `0c23a5a5` in:
   - `.dagger/runlint.go`
   - `mise.toml`
   - This file

## Why Not Use #nosec Comments?

Using `#nosec` everywhere makes it easy to suppress real issues without review. The baseline approach:
- Has a clear checkpoint in git history
- Prevents new violations of the same type
- Makes it harder to accidentally suppress real issues
- Documents all existing violations in one place (this file)
