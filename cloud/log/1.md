## Validation task (mise)

- Added `cloud:tf:validate` to top-level `mise.toml`.
- What it does:
  - Finds all dirs under `cloud/terraform` with `.tf` files
  - For each: `tofu init -backend=false -input=false` then `tofu validate`
- Note on `-backend=false`:
  - Skips remote backend config and uses a local throwaway backend for validation only.
  - Avoids contacting Spacelift/state; still downloads providers to type-check.

## Deployment Architecture

Two layers with different deployment methods:

**Infrastructure Layer (Automated):**
- Managed by: OpenTofu + Spacelift
- Location: `cloud/terraform/`
- Trigger: Auto-deploy on git push to main
- Includes: VMs, networks, firewalls, k3s installation

**Application Layer (Manual):**
- Managed by: kubectl (manual apply)
- Location: `cloud/k8s/`
- Trigger: Manual deployment via mise tasks
- Includes: Kubernetes resources (pods, services, etc.)
- Reason: Explicit control over application deployments

## Kubernetes Applications

### gVisor Runtime

- Directory: `cloud/k8s/gvisor/`
- Installed via cloud-init on VM boot
- RuntimeClass: `gvisor` (uses `runsc` handler)
- Deploy RuntimeClass: `mise run cloud:gvisor:deploy`
- Provides enhanced container isolation (syscall interception in userspace)

### Dagger Engine

- Directory: `cloud/k8s/dagger/`
- Deployment method: Kubernetes manifests (`deployment.yaml`)
- Runtime: gVisor (enhanced isolation)
- Deploy: `mise run cloud:dagger:deploy`
- Status: `mise run cloud:dagger:status`
- Uses `dagger.io/engine:latest` image
- Persistent storage via `local-path` storage class (20Gi)

**Deployment workflow:**
1. Push infrastructure changes (if any)
2. Wait for Spacelift to complete
3. Manually deploy: `mise run cloud:dagger:deploy`

## Troubleshooting

### Server Replacement on Every Apply

**Issue:** Server was being replaced on every Terraform run, even without config changes.

**Cause:** 
1. Using `.id` instead of `.name` for location, server_type, and image data sources
2. Hetzner API returns numeric IDs, but state had names stored
3. Terraform saw "nbg1" → "2" as a change requiring replacement

**Fix:** Changed to use `.name` for immutable attributes:
```hcl
# Before (causes replacement):
location = data.hcloud_location.nbg1.id  # Returns numeric ID "2"

# After (stable):
location = data.hcloud_location.nbg1.name  # Returns "nbg1"
```

**Note:** Legitimate replacements still happen when:
- `user_data` (cloud-init script) changes
- Other attributes marked as "forces replacement" change
