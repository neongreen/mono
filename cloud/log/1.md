## Validation task (mise)

- Added `cloud:tf:validate` to top-level `mise.toml`.
- What it does:
  - Finds all dirs under `cloud/terraform` with `.tf` files
  - For each: `tofu init -backend=false -input=false` then `tofu validate`
- Note on `-backend=false`:
  - Skips remote backend config and uses a local throwaway backend for validation only.
  - Avoids contacting Spacelift/state; still downloads providers to type-check.


## SSH key for servers (how we’ll add it)

- Source: public key from my workstation (`~/.ssh/id_ed25519.pub`). Public keys are safe to commit.
- How to record it in the repo:

```bash
mkdir -p cloud/terraform/01-hcloud
cat ~/.ssh/id_ed25519.pub > cloud/terraform/01-hcloud/ssh_key.pub
```

- Planned usage in Terraform (not applied yet, for reference):

```hcl
resource "hcloud_ssh_key" "workstation" {
  name       = "workstation"
  public_key = file("${path.module}/ssh_key.pub")
}

resource "hcloud_server" "vm1" {
  name        = "vm1"
  image       = data.hcloud_image.ubuntu_2404.id
  server_type = data.hcloud_server_type.cpx11.id
  location    = data.hcloud_location.nbg1.id
  ssh_keys    = [hcloud_ssh_key.workstation.id]
}

resource "hcloud_server_network" "vm1" {
  server_id  = hcloud_server.vm1.id
  network_id = hcloud_network.main.id
}

resource "hcloud_firewall_attachment" "vm1" {
  firewall_id = hcloud_firewall.default.id
  server_ids  = [hcloud_server.vm1.id]
}
```

- After committing `ssh_key.pub`, we’ll add the resources above, run a plan/apply in Spacelift, and SSH in as `root@<ipv4>`.
