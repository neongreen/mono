🚨 Demo 1: The Problem - Iframe Memory Leak

This demo shows how a buggy iframe can impact the parent page's performance and memory.

What's Happening?

  • Memory Leak: The iframe continuously creates objects without freeing them
  • Shared Process: The iframe runs in the same browser process as the parent page
  • Shared Memory: Both share the same JavaScript heap space
  • Impact on Parent: As iframe memory grows, the entire tab becomes sluggish
  • Potential Crash: If memory exceeds limits, the entire tab crashes

Why This Happens

Same-origin iframes (or iframes without proper isolation) share the same browser process and memory space as the parent page. This means:

  • Memory leaks in iframe affect parent page memory
  • CPU-intensive operations in iframe block parent page
  • Crashes in iframe can crash the parent page

How to Verify

  1. Open Chrome DevTools (F12)
  2. Go to Performance Monitor (Cmd/Ctrl + Shift + P → "Performance Monitor")
  3. Watch "JS heap size" increase when you start the leak
  4. Try interacting with the parent page - notice it becomes sluggish
  5. Open Chrome Task Manager (Shift + Esc) - see only one process for this tab

The Problem in Code

// Inside iframe - memory leak
let leakArray = [];
setInterval(() => {
  for (let i = 0; i < 10000; i++) {
    leakArray.push({ /* large object */ });
  }
}, 100);

This accumulates objects without limit, consuming more and more memory. Since the iframe shares process space with the parent, this affects the entire tab.

Why Sandbox Doesn't Help

<!-- This DOES NOT prevent memory leaks -->
<iframe sandbox="allow-scripts"></iframe>

The sandbox attribute restricts iframe capabilities (like accessing cookies, making requests, etc.) but it does NOT provide process isolation or memory isolation.
