✅ Demo 3: Cross-Origin Isolation (Recommended Solution)

The industry-standard approach for protecting parent pages from iframe issues.

✅ This is the Solution!

Cross-origin iframes run in separate browser processes, providing true isolation. Memory leaks and crashes in the iframe cannot affect the parent page.

How It Works

Parent Page: https://example.com
→ Process ID: 1234
→ Memory: 50 MB
→ Isolated from child
⬇️ postMessage() communication ⬇️
Iframe (Cross-Origin): https://sandbox.example.com
→ Process ID: 5678 (different!)
→ Memory: 200 MB (leaked)
→ Isolated from parent

Key Point: Different origins = Different processes = True isolation

❌ Same Origin (Bad)

<iframe src="/page.html">
  • ❌ Same process
  • ❌ Shared memory
  • ❌ No isolation
  • ❌ Crashes affect parent

✅ Cross-Origin (Good)

<iframe src="https://sandbox.example.com/page.html">
  • ✅ Separate process
  • ✅ Isolated memory
  • ✅ True isolation
  • ✅ Crashes don't spread

Implementation Guide

Step 1: Set Up Subdomain

Create a subdomain for your sandbox/preview environment:

Main site:    https://yourdomain.com
Sandbox:      https://sandbox.yourdomain.com

Configure DNS A/CNAME record pointing to your server.

Step 2: Configure CORS (If Needed)

If your iframe needs to make API calls to the main domain:

// On your API server
res.setHeader('Access-Control-Allow-Origin', 'https://sandbox.yourdomain.com');
res.setHeader('Access-Control-Allow-Credentials', 'true');

Step 3: Embed the Iframe

<!-- In your main page -->
<iframe 
  id="sandbox"
  src="https://sandbox.yourdomain.com/preview"
  sandbox="allow-scripts"
  style="width: 100%; height: 600px;">
</iframe>

Note: Adding sandbox provides additional security (defense in depth).

Step 4: Set Up Communication

Use postMessage for parent-iframe communication:

// In parent page
const iframe = document.getElementById('sandbox');

// Send message to iframe
iframe.contentWindow.postMessage({
  type: 'UPDATE_CODE',
  code: userCode
}, 'https://sandbox.yourdomain.com');

// Receive messages from iframe
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://sandbox.yourdomain.com') return;
  
  console.log('Received from iframe:', event.data);
});
// In iframe (sandbox.yourdomain.com)
// Receive messages from parent
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://yourdomain.com') return;
  
  if (event.data.type === 'UPDATE_CODE') {
    runCode(event.data.code);
  }
});

// Send message to parent
window.parent.postMessage({
  type: 'EXECUTION_COMPLETE',
  result: 'success'
}, 'https://yourdomain.com');

Step 5: Add Monitoring (Optional)

// Monitor iframe health
let iframeLoadCount = 0;
const MAX_RELOADS = 3;

iframe.addEventListener('load', () => {
  console.log('Iframe loaded successfully');
  iframeLoadCount = 0;
});

// Detect crashes (iframe unload without expected reason)
window.addEventListener('message', (event) => {
  if (event.data.type === 'IFRAME_CRASH') {
    iframeLoadCount++;
    if (iframeLoadCount < MAX_RELOADS) {
      console.warn('Iframe crashed, reloading...');
      iframe.src = iframe.src; // Reload
    } else {
      console.error('Iframe crashed too many times');
      showError('Preview unavailable');
    }
  }
});

Verification: How to Test It Works

Chrome Task Manager (Shift + Esc)

  1. Open Chrome Task Manager
  2. Load page with cross-origin iframe
  3. Look for separate process entries:
    • "Tab: yourdomain.com" - main page
    • "Subframe: sandbox.yourdomain.com" - iframe
  4. Each has separate memory counter

DevTools Memory Test

  1. Create memory leak in iframe
  2. Open DevTools Memory tab
  3. Take heap snapshot
  4. Trigger leak
  5. Take another snapshot
  6. Memory leak appears only in iframe process

Crash Test

  1. In iframe, trigger crash: while(true) { new Array(999999999); }
  2. Iframe will crash and show "Aw, Snap!"
  3. Parent page remains responsive
  4. Only iframe needs reload

Comparison Table

Feature Same-Origin Iframe Cross-Origin Iframe
Process Isolation ❌ No ✅ Yes
Memory Isolation ❌ Shared ✅ Separate
Crash Protection ❌ Parent affected ✅ Parent safe
Direct DOM Access ✅ Yes ❌ No (postMessage only)
Cookie Access ✅ Shared cookies ⚠️ Different cookies

Browser Support ✅ All browsers ✅ Modern browsers (Chrome 67+)

Common Pitfalls

1. Using Same Origin

❌ <iframe src="/preview"> 
   // Still same origin! No isolation.

2. Using Port Numbers

❌ <iframe src="http://localhost:8080">
   // Different port = different origin, BUT
   // localhost special handling may prevent isolation

3. Using about:blank or srcdoc

❌ <iframe src="about:blank">
❌ <iframe srcdoc="...">
   // Inherits parent origin! No isolation.

4. Not Validating Origins in postMessage

❌ window.addEventListener('message', (e) => {
     runCode(e.data); // Accept from ANY origin!
   });

✅ window.addEventListener('message', (e) => {
     if (e.origin !== 'https://sandbox.yourdomain.com') return;
     runCode(e.data);
   });

Local Development Setup

Option 1: Edit hosts file

# Add to /etc/hosts (Mac/Linux) or C:\Windows\System32\drivers\etc\hosts (Windows)
127.0.0.1 myapp.local
127.0.0.1 sandbox.myapp.local

Then access: http://myapp.local:8000 and http://sandbox.myapp.local:8000

Option 2: Use ngrok or similar

ngrok http 8000
# Creates: https://abc123.ngrok.io

# Set up second tunnel for sandbox
ngrok http 8001  
# Creates: https://xyz789.ngrok.io

🎯 Key Takeaways

  • ✅ Use cross-origin iframes for any untrusted or user-generated content
  • ✅ Different subdomain = Different process in modern browsers
  • ✅ Complete protection from memory leaks and crashes
  • ✅ Used by all major platforms (CodeSandbox, Figma, etc.)
  • ⚠️ Requires subdomain setup and postMessage communication
  • ⚠️ Cannot access iframe DOM directly - must use postMessage
