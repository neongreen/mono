🔒 Demo 4: COOP/COEP Headers (Advanced Isolation)

Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy for maximum isolation.

What are COOP/COEP?

COOP (Cross-Origin-Opener-Policy) and COEP (Cross-Origin-Embedder-Policy) are HTTP headers that enforce stricter cross-origin isolation boundaries.

They're required to enable powerful features like SharedArrayBuffer and high-resolution timers while maintaining security.

Why Use COOP/COEP?

  • Enable SharedArrayBuffer: Required for advanced features (WebAssembly threads, etc.)
  • Stricter isolation: Forces cross-origin resources to explicitly opt-in
  • Security: Protection against Spectre-like attacks
  • Performance: High-resolution timers without throttling

COOP (Cross-Origin-Opener-Policy)

Header Values:

Value Effect Use Case
unsafe-none Default behavior, no isolation Standard websites
same-origin-allow-popups Isolate but allow popups Apps that need popups
same-origin Strict isolation Maximum security

Server Configuration:

// Node.js / Express
app.use((req, res, next) => {
  res.setHeader('Cross-Origin-Opener-Policy', 'same-origin');
  next();
});

// Nginx
add_header Cross-Origin-Opener-Policy "same-origin";

// Apache
Header set Cross-Origin-Opener-Policy "same-origin"

What COOP Does:

  • Breaks relationships with windows opened via window.open()
  • Prevents cross-origin windows from accessing your window
  • Creates separate browsing context group
  • Enables cross-origin isolation

COEP (Cross-Origin-Embedder-Policy)

Header Values:

Value Effect Requirements
unsafe-none Default, no restrictions None
require-corp All resources must opt-in CORP headers on resources

Server Configuration:

// Node.js / Express
app.use((req, res, next) => {
  res.setHeader('Cross-Origin-Embedder-Policy', 'require-corp');
  next();
});

// Nginx
add_header Cross-Origin-Embedder-Policy "require-corp";

// Apache
Header set Cross-Origin-Embedder-Policy "require-corp"

What COEP Does:

  • Requires all embedded resources to explicitly allow it
  • Resources need Cross-Origin-Resource-Policy header
  • Enables crossOriginIsolated capability

CORP (Cross-Origin-Resource-Policy)

When using COEP, your resources (images, scripts, etc.) need CORP headers:

Value Meaning Use For
same-site Same site only Internal resources
same-origin Same origin only Sensitive resources
cross-origin Anyone can embed Public resources (CDN) 
// On resource responses
res.setHeader('Cross-Origin-Resource-Policy', 'cross-origin');

Complete Implementation Example

HTML with Meta Tags (Not Recommended):

<!DOCTYPE html>
<html>
<head>
  <!-- Less reliable, use HTTP headers instead -->
  <meta http-equiv="Cross-Origin-Opener-Policy" content="same-origin">
  <meta http-equiv="Cross-Origin-Embedder-Policy" content="require-corp">
</head>
<body>
  <script>
    console.log('Cross-origin isolated:', crossOriginIsolated);
  </script>
</body>
</html>

Node.js Server (Recommended):

const express = require('express');
const app = express();

// Apply COOP/COEP headers
app.use((req, res, next) => {
  res.setHeader('Cross-Origin-Opener-Policy', 'same-origin');
  res.setHeader('Cross-Origin-Embedder-Policy', 'require-corp');
  
  // For resources
  res.setHeader('Cross-Origin-Resource-Policy', 'cross-origin');
  
  next();
});

app.get('/', (req, res) => {
  res.send(`
    <!DOCTYPE html>
    <html>
    <body>
      <h1>Cross-Origin Isolated Page</h1>
      <script>
        console.log('Cross-origin isolated:', crossOriginIsolated);
        
        if (crossOriginIsolated) {
          // SharedArrayBuffer is available
          const sab = new SharedArrayBuffer(1024);
          console.log('SharedArrayBuffer created:', sab);
        }
      </script>
    </body>
    </html>
  `);
});

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000');
});

Checking If Isolation Works

// In your page JavaScript
if (crossOriginIsolated) {

  console.log('✅ SharedArrayBuffer is available');
  console.log('✅ High-resolution timers enabled');
  
  // You can now use SharedArrayBuffer
  const buffer = new SharedArrayBuffer(1024);
  
} else {
  console.log('❌ Page is NOT cross-origin isolated');
  console.log('Missing COOP/COEP headers?');
}

Before COOP/COEP:

crossOriginIsolated: false

typeof SharedArrayBuffer: 
  "undefined" (blocked)

performance.now() precision:
  ~0.1ms (throttled)

After COOP/COEP:

crossOriginIsolated: true

typeof SharedArrayBuffer:
  "function" (available)

performance.now() precision:
  ~0.005ms (full resolution)

Common Issues and Solutions

Issue 1: Resources Failing to Load

Error: Images, scripts, or other resources blocked

Solution: Add CORP headers to resources or use crossorigin attribute:

<!-- Add crossorigin attribute -->
<img src="https://cdn.example.com/image.jpg" crossorigin="anonymous">
<script src="https://cdn.example.com/script.js" crossorigin></script>

<!-- Or add CORP header on CDN -->
Cross-Origin-Resource-Policy: cross-origin

Issue 2: Third-Party Scripts Breaking

Problem: Analytics, ads, or third-party scripts don't work

Solution: Either:

  • Ask third-party to add CORP headers
  • Self-host the scripts
  • Use iframe without COEP for third-party content

Issue 3: OAuth/SSO Popups Breaking

Problem: window.open() for OAuth fails

Solution: Use same-origin-allow-popups instead of same-origin:

Cross-Origin-Opener-Policy: same-origin-allow-popups

Real-World Usage

StackBlitz WebContainers

StackBlitz uses COOP/COEP to enable WebContainers, which run Node.js entirely in the browser using SharedArrayBuffer. 

// StackBlitz sets these headers:
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

// This enables:
- SharedArrayBuffer for WebContainers
- Full Node.js runtime in browser
- File system emulation
- Package installation

Advanced Web Apps

  • Video/Audio Processing: Use SharedArrayBuffer for efficient data sharing between workers
  • WebAssembly: Enable threads and atomic operations
  • Game Engines: High-resolution timers for smooth rendering
  • Scientific Computing: Parallel processing with shared memory

});

⚠️ Important Considerations

  • Breaking Change: Enabling COOP/COEP can break existing functionality
  • Third-Party Content: May not work unless they support CORP
  • OAuth/Popups: May need same-origin-allow-popups
  • Testing Required: Thoroughly test before deploying to production
  • Browser Support: Modern browsers only (Chrome 88+, Firefox 79+, Safari 15.2+)

When to Use COOP/COEP

✅ Use When:

  • You need SharedArrayBuffer
  • You need high-resolution timers
  • You're building advanced web apps (IDEs, editors, games)
  • You want maximum security and isolation
  • You control all resources on your page

❌ Avoid When:

  • You rely heavily on third-party scripts
  • You need OAuth popups (use same-origin-allow-popups)
  • You embed content you don't control
  • Your CDN doesn't support CORP headers

Summary

COOP/COEP headers provide the strictest form of cross-origin isolation, enabling powerful features like SharedArrayBuffer. However, they require careful implementation and testing.

For most iframe isolation use cases, cross-origin iframes alone (Demo 3) are sufficient. Use COOP/COEP only when you specifically need SharedArrayBuffer or maximum security.
