⚡ Demo 5: Web Workers for Computation Isolation

Offload heavy computation to Web Workers to keep the main thread responsive.

What are Web Workers?

Web Workers run JavaScript in background threads, separate from the main UI thread. They're useful for CPU-intensive tasks that would otherwise block the UI.

❌ Without Web Worker

Heavy computation blocks UI:

Try clicking the button. The page will freeze during calculation!

✅ With Web Worker

UI stays responsive:

Page remains responsive during calculation!

How Web Workers Work

// Main thread (UI)
const worker = new Worker('worker.js');

// Send data to worker
worker.postMessage({ 
  task: 'calculate', 
  data: largeDataset 
});

// Receive result
worker.onmessage = (e) => {
  console.log('Result:', e.data.result);
  updateUI(e.data.result);
};

// Terminate if needed
worker.terminate();
// worker.js (runs in separate thread)
self.onmessage = (e) => {
  const { task, data } = e.data;
  
  // Heavy computation here
  const result = performComplexCalculation(data);
  
  // Send back to main thread
  self.postMessage({ result });
};

Worker Capabilities

Feature Available in Worker? Notes
JavaScript execution ✅ Yes Full JS support
DOM access ❌ No Cannot access document
XMLHttpRequest / fetch ✅ Yes Can make network requests
IndexedDB ✅ Yes Can access storage
setTimeout / setInterval ✅ Yes Timers work
Import scripts ✅ Yes Via importScripts()
Separate memory ✅ Yes Own heap space
Process isolation ⚠️ Limited Still same process

Use Cases for Web Workers

1. Data Processing

// Process large datasets without blocking UI
const worker = new Worker('data-processor.js');
worker.postMessage({ csv: largeCSVData });
worker.onmessage = (e) => {
  displayChart(e.data.processed);
};

2. Image/Video Processing

// Apply filters to images
worker.postMessage({ 
  imageData: ctx.getImageData(0, 0, width, height),
  filter: 'blur'
});
worker.onmessage = (e) => {
  ctx.putImageData(e.data.processedImage, 0, 0);
};

3. Syntax Highlighting / Code Analysis

// Used by CodeMirror, Monaco Editor
worker.postMessage({ code: userCode, language: 'javascript' });
worker.onmessage = (e) => {
  applyHighlighting(e.data.tokens);
};

4. Encryption / Hashing

// CPU-intensive crypto operations
worker.postMessage({ data: fileData, operation: 'encrypt' });
worker.onmessage = (e) => {
  saveEncryptedFile(e.data.encrypted);
};

Limitations

Still Shares Process

While Workers have separate JavaScript heaps, they still run in the same browser process. A Worker memory leak can still affect the tab: 

// worker.js - This WILL affect the tab!
let leakyArray = [];
setInterval(() => {
  leakyArray.push(new Array(100000).fill('leak'));
  // Memory grows in same process as main thread
}, 100);

No DOM Access

Workers can't manipulate the DOM. All UI updates must happen in main thread.

Communication Overhead

Data is copied (not shared) between worker and main thread by default:

// This COPIES the data (can be slow for large objects)
worker.postMessage(largeObject);

// Use Transferable Objects for zero-copy transfer
worker.postMessage(arrayBuffer, [arrayBuffer]);

Transferable Objects (Performance)

For large data, use Transferable Objects to avoid copying: 

// Instead of copying (slow)
const buffer = new ArrayBuffer(1024 * 1024); // 1MB
worker.postMessage({ buffer }); // Copies 1MB

// Transfer ownership (fast, zero-copy)
const buffer = new ArrayBuffer(1024 * 1024);
worker.postMessage({ buffer }, [buffer]);
// buffer is now empty in main thread, ownership transferred

Transferable types:

  • ArrayBuffer
  • MessagePort
  • ImageBitmap
  • OffscreenCanvas

Combining with Cross-Origin Iframes

For maximum isolation, use BOTH: 

<!-- Cross-origin iframe for process isolation -->
<iframe src="https://sandbox.yourdomain.com"></iframe>

<script>
  // Inside iframe: Use Web Worker for computation
  const worker = new Worker('heavy-computation.js');
  worker.postMessage({ data: userCode });
</script>

This gives you:

  • ✅ Process isolation (cross-origin iframe)
  • ✅ UI responsiveness (Web Worker)
  • ✅ Separate memory heaps (both)
  • ✅ Protection from crashes (cross-origin)

Summary

  • Web Workers: Great for keeping UI responsive during heavy computation
  • Separate heap: Workers have their own JavaScript heap
  • Not process isolation: Still shares same browser process
  • Best practice: Combine with cross-origin iframes for complete protection
  • Use for: Data processing, image/video work, syntax highlighting, crypto
