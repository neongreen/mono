# want - Design

Interactive task fulfillment tool for macOS.

## Core Concept

`want` helps you get things you need on your system. It's a task fulfillment assistant, not a state manager.

The goal is making things available when you need them, not maintaining exact system state.

## Interaction Model

Primary interaction is through CLI commands:

```bash
want jujutsu
want github.com/user/repo
want binary https://example.com/tool
```

When multiple options exist, the tool prompts:

```bash
$ want jujutsu

Multiple options available:
  1. Install via mise
  2. Install via Homebrew
  3. Download from GitHub releases
  4. Build from source (requires Rust)

Which would you prefer? [1]: 
```

Preferences are remembered for future use.

## Design Principles

### Under-constrain by default

`want jujutsu` means "make jujutsu available", not "install specific version from specific source".

### Preserve existing work

If a repository is already cloned on a feature branch, don't reset it to main.

```bash
$ want github.com/user/myproject

Checking github.com/user/myproject...
✓ Repository already cloned at ~/projects/myproject
✓ Currently on branch: feature-work
```

### Temporary vs persistent

```bash
want --temp setup-jj-here   # Don't record
want jujutsu                # Record as requirement
```

### Preferences

The tool learns your choices:

```yaml
# ~/.config/want/preferences.yaml
preferences:
  package_sources:
    default: [mise, homebrew, github-release, build-from-source]
  jujutsu:
    prefer: mise
```

## Use Cases

### Install a tool

```bash
$ want jujutsu

Found options:
  • Via mise: jujutsu 0.23.0
  • Via Homebrew: jujutsu 0.22.0
  • Via GitHub releases: jujutsu 0.23.0
  • Build from source: latest

Install via mise? [Y/n]: y

Installing jujutsu via mise...
✓ jujutsu available
```

### Clone a repository

```bash
$ want github.com/neongreen/mono

Where should I clone it?
  1. ~/projects/mono (default)
  2. ~/code/mono
  3. Custom path

Choice [1]: 

✓ Repository cloned to ~/projects/mono
```

### Setup in current directory

```bash
$ cd ~/projects/myrepo
$ want jujutsu-setup-here

Prerequisites:
  • jujutsu (available)

Proceed? [Y/n]: y

✓ Jujutsu initialized
```

### Download binary

```bash
$ want binary https://github.com/user/tool/releases/download/v1.0/tool-macos

✓ Downloaded to ~/.local/bin/tool
✓ Made executable
```

### Install MCP server

```bash
$ want mcp-server @modelcontextprotocol/server-filesystem

Prerequisites:
  • node: available
  • npx: available

Add MCP server to Claude config? [Y/n]: y

✓ Added to Claude config
```

## Architecture

### Components

```
want
├── cli/              # Command-line interface
│   ├── commands.go   # want, list, forget, preferences
│   └── ui.go         # Interactive prompts
├── resolver/         # Requirement resolution
│   ├── resolver.go   # Find ways to satisfy requirements
│   ├── options.go    # Evaluate different paths
│   └── preferences.go # User preference handling
├── providers/        # Different ways to get things
│   ├── mise.go
│   ├── homebrew.go
│   ├── github.go
│   ├── build.go
│   └── download.go
├── checker/          # Check if requirements are satisfied
│   └── checker.go
└── config/           # Configuration storage
    ├── wants.go      # What user has asked for
    └── preferences.go # User preferences
```

### Configuration

Config location: `~/.config/want/`

```yaml
# wants.yaml - What you've asked for
wants:
  - name: jujutsu
    satisfied_by: mise
    installed_at: 2024-01-15T10:30:00Z
    
  - name: github.com/user/repo
    satisfied_by: git-clone
    path: ~/projects/repo
    installed_at: 2024-01-15T11:00:00Z

# preferences.yaml - Your preferences
preferences:
  package_sources:
    priority: [mise, homebrew, github-release]
  
  specific:
    jujutsu:
      prefer: mise
```

## Commands

### `want <requirement>`

```bash
want jujutsu                    # Get a tool
want github.com/user/repo       # Get a repository
want binary https://...         # Get a binary from URL
want mcp-server @scope/name     # Setup MCP server
```

Options:
- `--temp` - Don't record permanently
- `--path <path>` - Specific installation path
- `--via <provider>` - Force specific provider

### `want list`

```bash
$ want list

  ✓ jujutsu (via mise, v0.23.0)
  ✓ github.com/user/repo (at ~/projects/repo)
  ✗ old-tool (no longer available)
```

### `want check`

```bash
$ want check

  ✓ jujutsu: available
  ✓ github.com/user/repo: cloned
  ✗ removed-tool: not found
```

### `want forget <requirement>`

Remove from tracking (doesn't uninstall).

### `want preferences`

Manage preferences interactively.

## Key Decisions

### CLI over YAML

YAML config is generated by CLI commands, not edited manually.

### Interactive when needed

Prompt for choices instead of requiring upfront configuration.

### Preferences over strict config

Store simple preferences (e.g., "prefer mise") rather than exact specifications.

### Preserve existing work

Don't checkout branches, pull changes, or reset state in existing repositories.

## Implementation Plan

### Phase 1: Core
- `want` command for packages via Homebrew
- `want` command for git repositories
- Basic preferences system
- `want list` and `want check`

### Phase 2: Smart Resolution
- Multiple provider support (mise, Homebrew, GitHub)
- Interactive option selection
- Preference learning

### Phase 3: Advanced Use Cases
- Binary downloads from URLs
- MCP server setup
- Build-from-source option

### Phase 4: Polish
- Error handling
- Documentation
- Testing
